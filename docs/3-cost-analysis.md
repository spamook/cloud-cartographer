# Migration cost analysis

The monthly cost of running the sample application with its monitoring stack and CI/CD on AWS and
on Google Cloud, broken down by environment, component and line item.

- Unit prices: [`cost-model/prices.toml`](../cost-model/prices.toml). Each price links to its official
  pricing page and was checked on 2026-11-08.
- Quantities: [`cost-model/bom.toml`](../cost-model/bom.toml).
- The tables below are generated by [`cost-model/calc.py`](../cost-model/calc.py), so changing an
  assumption is one edit and one command:

```bash
python cost-model/calc.py --write
```

## What is priced

Three environments per provider, laid out as in the [provider comparison](2-provider-comparison.md):

| | Shared | Test | Prod |
|---|---|---|---|
| Account / project | `shared` / `cc-shared` | `test` / `cc-test` | `prod` / `cc-prod` |
| Kubernetes | — | 1 cluster: EKS / GKE zonal | 1 cluster: EKS / GKE regional, 3 zones |
| Node groups (`main` · `monitoring` · `tools`) | — | 1 · 1 · 1 node, plus a CI node a few hours a day | 3 (one per zone, +1 at the daily peak) · 1 · 1 |
| Database | — | single zone, small burstable | Multi-AZ / HA, 30 daily backups, 7 days PITR |
| Other | GitLab VM, WireGuard VPN, registry, public DNS zone, domain | NAT, external + internal load balancer, private DNS zone, log bucket | NAT in every zone, external + internal load balancer, private DNS zone, log bucket |

- **Region**: AWS eu-north-1 (Stockholm), Google Cloud europe-north1 (Finland).
- **Prices**: USD, 730 hours per month, without VAT.

### Sizing and where it comes from

| Item | Size | Why |
|---|---|---|
| `main` nodes | 2 vCPU, 4 GB (t4g.medium / e2-medium) | The app (frontend + backend) is small. Three nodes give one per zone for HA, and the autoscaler adds a fourth at the daily peak |
| `monitoring` node | 2 vCPU, 8 GB (t4g.large / e2-standard-2) | Measured idle footprint: Prometheus 290 MiB, Grafana 435 MiB, Loki 160 MiB, exporters ~70 MiB. Prometheus memory grows with series (×2–3 for a 5-node cluster), so 8 GB leaves headroom |
| `tools` node | 2 vCPU, 4 GB | Argo CD (~0.5 GB), ExternalDNS, the load balancer controller, cluster autoscaler, External Secrets (~0.15 GB), cert-manager. CI jobs run on a separate Spot node that exists only while jobs run |
| Prod database | 2 vCPU burstable, 4 GB Multi-AZ / 1 vCPU, 3.75 GB HA | The local PostgreSQL handled ~2,900 TPS (pgbench, 16 clients) on 2 cores. The app needs a small fraction of that. Google's shared-core instances have no SLA, so prod uses a dedicated vCPU |
| Prometheus volume | 50 GB | 30 days × ~5,000 samples/s × 1–2 bytes per sample ≈ 13–26 GB, plus WAL and headroom |
| Logs | 2 GB/day received, ~8× compression, kept 365 days → ~91 GB in the bucket | **Assumption until the app run**: ~250 bytes of access and app log per request at ~100 requests/s on average. Loki's compression is measured in [03-log-volume](../measurements/03-log-volume/summary.md) |
| Internet egress | 1,000 GB/month | **Assumption until the app run**: ~1 MB per user session (first page load ~0.6 MB, API calls ~0.4 MB) × ~1 million sessions a month (peak of 1,000 simultaneous users, ~250 on average over the day, 10-minute sessions) |

These are the parameters at the top of `bom.toml`. The two assumptions are replaced by the measured
values of the sample app under load, and the tables below are regenerated.

### Hidden cost: log accumulation over the first year (prod)

Loki receives 2 GB of log lines a day and stores them compressed (~8×); logs are kept 365 days, so the bucket grows every month until the first deletions start in month 13.

| Month | Stored in the bucket | AWS S3 Standard | Cloud Storage Standard |

## Comparing the providers

- **The totals are close.** AWS ends up about 10–15% more expensive on demand, and the gap widens
  slightly in the optimised scenario. The difference comes from a few lines, not from the
  servers, which cost about the same.
- **Kubernetes control planes.** Both charge $0.10/h per cluster, but Google's free tier pays for
  one zonal cluster, so the test cluster costs nothing there. AWS pays $73/month for each.
- **NAT.**
  - AWS bills every NAT gateway ($34/month each). An HA prod setup needs one per zone, three in
    all, and each gateway also uses a paid public IPv4 address.
  - Google's Cloud NAT is a regional service billed per VM ($1/month per node), so it costs a
    few dollars.
  - This is the largest single structural difference.
- **Public IPv4 addresses.** AWS charges $3.65/month for every address, including the ALB's address
  in each zone and the NAT gateways' addresses. Google doesn't charge for load balancer addresses.
- **Load balancers.** These go the other way.
  - AWS ALB/NLB: $17.5/month each plus capacity units.
  - Google: $20.4/month per forwarding rule plus $0.009 per GB processed, so the data-processing
    part grows with traffic.
- **Egress.** Google's Premium Tier costs $0.12/GiB against AWS's $0.09/GB, and AWS gives the first
  100 GB free. At 1 TB a month that makes Google ~$40 more expensive on this line. Google's Standard
  Tier ($0.085/GiB) would close the gap at the price of routing over the public internet.
- **Database.**
  - RDS Multi-AZ with a burstable instance is the cheaper HA database.
  - Cloud SQL HA needs a dedicated vCPU and pays for its SSD twice. It includes the 30-backup /
    7-day-log configuration the requirement asks for exactly.
- **Storage.** EBS gp3 ($0.0836) is cheaper than Google's balanced disk ($0.11). Object storage for
  logs is a little cheaper on Google ($0.020 against $0.023).

## Hidden cost considerations

### Data transfer between services

| Path | AWS | Google Cloud | In the estimate |
|---|---|---|---|
| Load balancer → pods in other zones; backend → database primary in another zone; Prometheus scraping nodes in other zones | $0.01/GB each way | $0.01/GiB | 100 GB/month in prod |
| Nodes → internet through NAT (OS updates, external APIs, pulls that miss the endpoint) | $0.046/GB processed + egress | $0.045/GiB + egress | 50 GB/month prod, 20 GB test |
| Image pulls from the registry | free in-region, **but through the NAT gateway unless the S3 gateway endpoint is used** | free in-region with Private Google Access | S3 endpoint / Private Google Access, so images and Loki chunks skip NAT |
| Argo CD and runners ↔ GitLab in the shared network | VPC peering $0.01/GB each way | billed as inter-zone | 5 GB/month |
| Load balancer data processing | in LCUs (1 LCU ≈ 1 GB/h of processed bytes) | $0.009/GB in and out | ~1 TB/month in prod |
| Replication of the database to its standby | free (Multi-AZ) | free (HA) | — |

Two things make data transfer the easiest cost to underestimate. First, it grows with traffic, not
with the infrastructure: double the users, double the egress. Second, it is spread over many small
line items. Together the transfer lines are about 15–25% of the prod bill here.

### Storage beyond the base allocation

- **Backups.**
  - RDS keeps automated backups free up to the size of the provisioned storage (20 GB), per account
    and region. Thirty daily backups of a database of about 1 GB stay inside that. A growing database,
    or manual snapshots kept forever, start costing $0.09/GB-month.
  - Cloud SQL charges every backup GB ($0.088), so 30 retained backups are always billed.
- **Log accumulation.** Logs are kept a year, so the bucket grows every month for 12 months before
  deletions start. Month 1 costs cents, month 12 about 12 times as much, and the first year
  averages half the steady state (table above). A debug log level left on in prod can multiply the
  daily volume by 5–10.
- **Metrics.** Prometheus keeps 30 days on its volume. More nodes or pods mean more series, and the
  volume must grow with them. The size-based retention limit (`retentionSize`) stops a full disk
  from crashing Prometheus.
- **Snapshots and images.** Without lifecycle rules, registry images and disk snapshots grow
  forever. The design keeps the last 30 image tags and 7 daily snapshots.

### Other easy-to-miss items

- AWS charges for every public IPv4 address: $22/month in prod.
- EKS on a Kubernetes version past standard support costs $0.60/h instead of $0.10/h, an extra
  $365/month per cluster.
- Google's defaults cost money until they are switched off: GKE workload logs in Cloud Logging,
  Managed Service for Prometheus and 100 GB boot disks.
- AWS Client VPN would cost ~$110/month per associated subnet plus $0.05 per connection-hour. The
  WireGuard instance costs ~$7.

## Alternatives that change the total

| Option | Monthly effect | Trade-off |
|---|---|---|
| **GitLab.com Free** instead of the GitLab VM (self-managed runners stay) | −$140 AWS / −$125 Google | At most 5 users in a private group (read-only above that), 10 GiB per project, code hosted outside our accounts; runners and Argo CD reach gitlab.com through NAT |
| **GitLab.com Premium**, 8 users × $29 | +$90 AWS / +$105 Google vs the VM | No GitLab administration, 10,000 compute minutes; per-user price grows with the team |
| **GitLab-hosted runners** instead of runners in the cluster | ~+$29 (≈3,300 minutes/month: 400 free, then $10 per 1,000) | Nothing to run, but every pipeline minute is metered |
| **One NAT gateway** in AWS prod instead of three | −$67 | A zone outage takes outbound internet away from the nodes in the other zones |
| **AWS Client VPN** instead of WireGuard | +$110 to +$220 | Managed, integrates with SSO; much more expensive |
| **Google Standard Tier** egress | −$35 | Traffic crosses the public internet longer; slightly higher latency |
| **3-year commitments** instead of 1-year | another −20…−30% on committed lines | Locked in before the real usage is known |

## Recommendation

Both providers fit the requirements at a similar price, roughly $920–1,050 a month on demand and
$680–820 optimised.

- **Google Cloud is cheaper for this design:**
  - one free cluster;
  - cheap regional NAT;
  - no charge for load balancer addresses.
- **AWS is cheaper on egress and on the HA database,** and it would win if traffic, and with it
  egress, grew substantially.

The bigger lever is the same on both: put test on Spot capacity with working hours, and commit to
the always-on prod baseline after a month of real usage. That cuts 20–27% without changing the
architecture.
